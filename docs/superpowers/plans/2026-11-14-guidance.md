# 이동 중 길 안내(내비게이션) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 경로가 나온 화면에서 "안내 시작"이나 "미리 보기"를 누르면, 다음에 할 일(꺾기·엘리베이터·경사로·가파른 구간·도착)을 글자와 목소리로 미리 알려 주고, 길에서 벗어나면 다시 찾아 주는 안내 화면을 더한다.

**Architecture:** 안내 계산은 화면과 무관한 순수 Dart 두 파일이다. `lib/cues.dart`가 경로에서 안내 지점을 뽑고, `lib/guidance.dart`가 위치를 받을 때마다 진행 위치·벗어남·다시 찾기·도착을 판단해 "지금 말할 문장"을 돌려준다. 안내 화면은 평소 화면 위에 새 화면으로 띄우므로(`Navigator.push`) 평소 화면은 건드리지 않는다. 안내 화면의 지도는 지도 그림(타일) 없이 flutter_map의 도형 층(건물 테두리·길·경로)만으로 그리고, 건물 이름은 돌지 않는 층에 따로 얹는다. 미리 보기는 실제 위치 대신 0.1초마다 경로 위의 점을 같은 계산에 넣는다.

**Tech Stack:** Flutter 3.47.6 / Dart 3.13.5, flutter_map 8.3.2(`MapController.moveAndRotate`, `PolygonLayer`, `MarkerLayer(rotate: true)`), 새 패키지 flutter_tts 4.2.5 · wakelock_plus 1.8.0. 나머지는 지금 그대로.

**Spec:** `docs/superpowers/specs/2026-11-14-guidance-design.md` (아래에서 "설계서". 처음 설계서는 `2026-11-10-jnu-wheelchair-nav-design.md`)

## Global Constraints

- 새로 넣는 패키지는 `flutter_tts`, `wakelock_plus` 둘뿐이다.
- 바꾸지 않는다: iOS Bundle Identifier, 저장 열쇠 `survey_records`, 조사 기록 JSON 형식, `assets/campus.json`, `assets/survey.json`, `tool/fetch_campus.dart`(고치지도 다시 돌리지도 않는다).
- 평소 화면(지도 탭의 검색·경로 요약, 조사 탭)의 모습과 동작은 그대로다. 더하는 것은 경로 요약의 버튼 두 개뿐이다. 평소 화면에서는 지금처럼 위치가 바뀌어도 길을 다시 찾지 않는다.
- 지금 있는 테스트 51개는 고치지 않고 모두 통과해야 한다.
- 길은 언제나 기존 `findRoute`로 찾는다. 계단 조각은 다시 찾은 길에도 들어가지 않는다.
- 왼쪽·오른쪽은 가는 방향 기준이다. `xy` 평면(x 동쪽, y 북쪽)에서 반시계 방향으로 꺾이면 왼쪽이다.
- 조정값은 모두 `lib/model.dart` 맨 위 상수다(Task 1의 표).
- 음성, 화면 켜 두기, 위치 기능이 없거나 실패해도 앱이 멈추지 않는다. 그 기능을 부르는 곳은 모두 오류를 삼킨다. 소리가 안 나도 글자 안내는 나온다.
- 화면 글자는 한국어. 이 계획서에 따옴표로 적힌 문구는 그대로 쓴다.
- 누르는 대상은 48px 이상, 아이콘만 있는 버튼에는 `tooltip`. 색만으로 구분하지 않는다.
- 안내 화면에도 "OpenStreetMap contributors"가 보인다. 나침반과 추가 위치 권한은 쓰지 않는다.
- 내려받기 요청의 User-Agent는 `wheel-nav-fetch/1.0`.
- 미리 보기가 돌아가는 화면 테스트에서는 `pumpAndSettle`을 쓰지 않는다(0.1초마다 도는 타이머 때문에 끝나지 않는다). `pump(시간)`만 쓴다.

- 설계서 9절 순서와 다른 점: 다시 찾기 계산(설계서의 5번째)을 화면보다 먼저(Task 3) 만든다. 화면 없이 테스트할 수 있기 때문이다.

## 설계서에 덧붙인 결정 (사용자가 읽고 바꿀 수 있다)

1. 조정값 세 개를 더한다: 진행 위치를 찾는 범위 50m, 엘리베이터 위에서 믿어 주는 거리 60m, 지도 방향을 재는 구간 15m (Task 1 표의 아래 세 줄).
2. 한순간에 말할 것이 여러 개면(예: 꺾자마자 가파른 구간) 한 번에 이어서 말한다. 따로 말하면 뒤의 말이 앞의 말을 끊는다.
3. 말한 문장을 안내 화면 아래에 글자로도 보여 준다(자막). 소리를 껐거나 소리가 안 나는 기기에서도 "경로를 다시 찾았습니다"를 볼 수 있다.
4. 엘리베이터 위에 있어도 경로에서 60m 넘게 떨어지면 벗어난 것으로 본다. 설계서대로만 하면 엘리베이터 입구를 지나쳐 계속 가도 영영 다시 찾지 않는다.
5. 오차가 큰 위치(30m 초과)는 경로에서 25m 안이면 진행 위치에만 쓰고, 밖이면 버린다.
6. "안내 시작"을 누르면 그 순간의 내 위치에서 길을 한 번 다시 찾고 시작한다(목적지를 고른 뒤 이동했을 수 있다).
7. 도착은 미리 말하지 않고 도착했을 때만 말한다(도착 거리 15m가 미리 알리는 거리 20m보다 짧아 두 말이 겹친다).
8. 실제 안내에서 지도는 위치가 들어올 때마다(약 1초에 한 번) 움직인다. 미리 보기는 0.1초마다 움직인다.

- Produces (`lib/cues.dart`):
  - `enum CueKind { left, right, uturn, elevator, ramp, steep, arrive }`
  - `class Cue { const Cue(this.kind, this.at, [this.meters = 0]); final CueKind kind; final double at; final double meters; }` — `at`은 경로 시작에서 이 지점까지의 거리(m), `meters`는 가파른 구간의 길이(`steep`만).
  - `double bearing(LatLng a, LatLng b)` — a에서 b를 보는 방향. 북쪽 0, 시계 방향, 도. `xy` 차이로 `atan2(dx, dy)`.
  - `double leftTurn(double from, double to)` — 방향 `from`에서 `to`로 꺾인 각. 왼쪽이 +, 범위 (−180, 180].
  - `CueKind? turnKind(double left)` — `|left| ≥ uturnDegrees`면 `uturn`, `|left| < turnDegrees`면 null, 그 밖에는 부호에 따라 `left`/`right`.
  - `List<Cue> cuesFor(RouteResult r)` — 거리 순서. 마지막은 항상 `arrive`(`at` = 전체 길이).
  - `String cueTitle(Cue c, String destName)`, `String bannerText(Cue c, double metersTo, String destName)`, `String cueSpeech(Cue c, double metersTo)`, `const arrivedSpeech = '목적지에 도착했습니다. 안내를 마칩니다';`
- Produces (`test/helpers.dart`):
  - `(Graph, RouteResult) net(List<LatLng> nodes, List<(int, int)> edges, LatLng from, LatLng to, {List<SurveyRecord> records = const [], double Function(LatLng) h = flat, Profile p = Profile.manual})` — `buildGraph` 뒤 `findRoute(...)!`.

List<Cue> cuesFor(RouteResult r) {
  final legs = r.legs, n = legs.length;
  final starts = <double>[0]; // starts[i] = 조각 i가 시작되는 곳까지의 거리
  for (final l in legs) {
    starts.add(starts.last + l.meters);
  }
  // turn[i] = 조각 i가 시작되는 점에서 꺾인 각(왼쪽 +). 0.5m 미만 조각의 방향은 믿지 않고,
  // 엘리베이터 조각의 양 끝은 0으로 둔다(지도의 엘리베이터 선은 실제로 지나는 길이 아니다).
  final turn = List.filled(n, 0.0);
  double? before;
  for (var i = 0; i < n; i++) {
    final l = legs[i];
    if (l.meters < 0.5) continue;
    final now = bearing(l.a, l.b);
    final elevator =
        l.kind == Kind.elevator || (i > 0 && legs[i - 1].kind == Kind.elevator);
    if (before != null && !elevator) turn[i] = leftTurn(before, now);
    before = now;
  }
  final cues = <Cue>[];
  final used = List.filled(n, false);
  for (var i = 1; i < n; i++) {
    if (used[i] || turn[i] == 0) continue;
    // i에서 cornerMeters 안에 있고 같은 쪽으로 꺾이는 점들을 한 모퉁이로 묶는다.
    final corner = [
      for (var j = i; j < n && starts[j] - starts[i] <= cornerMeters; j++)
        if (!used[j] && turn[j].sign == turn[i].sign) j,
    ];
    final kind = turnKind(corner.fold(0.0, (sum, j) => sum + turn[j]));
    if (kind == null) continue;
    for (final j in corner) {
      used[j] = true;
    }
    // 가장 크게 꺾이는 점을 모퉁이의 자리로 삼는다.
    final peak = corner.reduce((a, b) => turn[b].abs() > turn[a].abs() ? b : a);
    cues.add(Cue(kind, starts[peak]));
  }
  for (var i = 0; i < n; i++) {
    final l = legs[i], prev = i == 0 ? null : legs[i - 1];
    if (l.kind == Kind.elevator && prev?.kind != Kind.elevator) {
      cues.add(Cue(CueKind.elevator, starts[i]));
    }
    if (l.kind == Kind.ramp && prev?.kind != Kind.ramp) {
      cues.add(Cue(CueKind.ramp, starts[i]));
    }
    if (l.steep && prev?.steep != true) {
      var end = i;
      while (end < n && legs[end].steep) {
        end++;
      }
      cues.add(Cue(CueKind.steep, starts[i], starts[end] - starts[i]));
    }
  }
  // 거리 순서로. 같은 자리면 넣은 순서(꺾임 → 엘리베이터·경사로·가파른 구간)를 지킨다.
  final order = [for (var i = 0; i < cues.length; i++) i]
    ..sort((a, b) => cues[a].at != cues[b].at
        ? cues[a].at.compareTo(cues[b].at)
        : a.compareTo(b));
  return [for (final i in order) cues[i], Cue(CueKind.arrive, starts.last)];
}

### Task 6: 직접 그리는 지도

**Files:**
- Create: `lib/guidance_map.dart`, `test/guidance_map_test.dart`

**Interfaces:**
- Consumes: 기존 `routeLines(RouteResult)`, `routeMarkers(RouteResult)`(`lib/route_tab.dart`), `overlayLines(Graph, stairsOnly: true)`(`lib/survey_tab.dart`), `Campus`, `Place`, `Graph`.
- Produces (`lib/guidance_map.dart`):
  - `class GuidanceMap extends StatelessWidget` — `const GuidanceMap({super.key, required MapController controller, required Campus campus, required Graph graph, required List<List<LatLng>> buildings, required RouteResult route, required Place dest, required LatLng position, required double heading, void Function(LatLng)? onTap})`. `position`과 `heading`은 처음 화면의 가운데와 방향(`initialCenter`, `initialRotation: -heading`, `initialZoom: guidanceZoom`)이고 내 위치 표시의 자리다. 그 뒤 지도를 움직이는 것은 `controller`를 가진 쪽(Task 7)이 한다.
  - `List<int> keepLabels(List<Rect> rects)` — 앞에서부터 보며, 이미 남긴 것과 겹치지 않는 것의 번호만 남긴다.
  - `class NameLayer extends StatelessWidget` — `const NameLayer({super.key, required List<Place> places})`. `FlutterMap`의 자식으로 넣는다.

그리는 순서(아래에서 위로). 지도 그림 층(`TileLayer`)은 넣지 않는다:
1. 바탕색: `MapOptions.backgroundColor`
2. 건물: `PolygonLayer` — `buildings`마다 옅은 채움과 테두리
3. 길: `PolylineLayer` — `graph.edges` 가운데 계단이 아닌 조각 전부(찻길과 조사로 확인된 길)
4. 막힌 계단: `overlayLines(graph, stairsOnly: true)`
5. 경로: `routeLines(route)`
6. 표시: `MarkerLayer(rotate: true, …)` — `routeMarkers(route)`, 목적지 핀(`dest.at`, 평소 화면과 같은 모양), 내 위치(`position`, `Semantics(label: '내 위치')`). `rotate: true`라서 지도가 돌아도 아이콘은 바로 서 있다. 표시는 모두 `IgnorePointer`로 감싼다.
7. 건물 이름: `NameLayer(places: [dest, ...나머지 장소])` — 목적지 이름이 맨 먼저라 가려지지 않는다.
8. `SimpleAttributionWidget(source: Text('OpenStreetMap contributors'))`

손짓: `InteractionOptions(flags: InteractiveFlag.pinchZoom | InteractiveFlag.scrollWheelZoom)` — 손으로 옮기거나 돌릴 수 없고 확대·축소만 된다. `minZoom: 15`, `maxZoom: 20`. `onTap: (_, p) => onTap?.call(p)`.

`NameLayer`: flutter_map은 `MobileLayerTransformer`로 감싼 층만 지도와 함께 돌린다. 이 층은 감싸지 않으므로 돌지 않는다. `MapCamera.of(context).latLngToScreenOffset(place.at)`로 화면 자리를 얻고, `TextPainter`로 글자 크기를 재어 그 자리가 가운데인 네모를 만든 뒤(가운데가 화면 밖이면 뺀다) `keepLabels`로 남은 것만 `Positioned` + `Text`로 놓는다. 전체를 `IgnorePointer`로 감싼다.
