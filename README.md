# 제주대 휠체어 길안내

제주대학교 아라캠퍼스에서 계단을 피하고, 가파른 길은 미리 알려 주는 길 안내 앱입니다.
아이폰·안드로이드·웹에서 같은 코드로 돌아갑니다.

- 설계서: `docs/superpowers/specs/2026-11-10-jnu-wheelchair-nav-design.md`
- 명령어는 모두 **터미널**(맥의 "터미널" 앱)에서, 이 폴더로 이동한 뒤 입력합니다.
  ```
  cd Jeju-National-University-Campus-Barrier-Free-App
  ```

---

## 1. 컴퓨터에서 열어 보기 (가장 쉬운 확인 방법)

```
flutter run -d chrome --web-port 5300
```

크롬 창이 열리고 앱이 뜹니다. 끝낼 때는 터미널에서 `q`를 누릅니다.

> `--web-port 5300`을 꼭 붙이세요. 주소가 매번 같아야 브라우저에 저장된 조사 기록이 다음에도 보입니다.

---

## 2. 조사자 아이폰에 처음 설치하기

준비물: 맥, 아이폰, 연결 케이블, 애플 계정(무료 계정으로 충분).

### 2-1. 맥에 애플 계정 넣기 (한 번만)

1. **Xcode**를 엽니다.
2. 위쪽 메뉴 **Xcode → Settings…(설정) → Accounts(계정)** 로 갑니다.
3. 왼쪽 아래 **+** 를 누르고 **Apple Account**를 골라 로그인합니다.

### 2-2. 아이폰 연결하고 개발자 모드 켜기 (한 번만)

1. 아이폰을 케이블로 맥에 연결합니다.
2. 아이폰에 "이 컴퓨터를 신뢰하겠습니까?"가 뜨면 **신뢰**를 누르고 암호를 입력합니다.
3. 아이폰에서 **설정 → 개인정보 보호 및 보안 → 개발자 모드**를 켭니다.
   (이 메뉴가 안 보이면 아래 2-3을 먼저 한 번 해 보세요. 맥의 Xcode와 한 번 연결돼야 나타납니다.)
4. 아이폰이 다시 켜지면 "개발자 모드를 켜시겠습니까?"에서 **켜기**를 누릅니다.

### 2-3. 앱에 "만든 사람" 정보 넣기 (한 번만)

1. 터미널에 입력합니다.
   ```
   open ios/Runner.xcworkspace
   ```
2. Xcode 왼쪽 맨 위의 파란 아이콘 **Runner**를 누릅니다.
3. 가운데에서 **TARGETS 아래의 Runner → Signing & Capabilities** 탭을 누릅니다.
4. **Automatically manage signing**에 체크하고, **Team**에서 본인 이름 **(Personal Team)** 을 고릅니다.
5. 빨간 오류가 사라지면 Xcode를 닫아도 됩니다.

> **Bundle Identifier**(`kr.jnucapstone3.jnuWheelNav`)는 바꾸지 마세요.
> 바꾸면 아이폰이 "다른 앱"으로 보고, 전에 기록한 조사 내용이 보이지 않습니다.

### 2-4. 설치하기

1. 아이폰 화면 잠금을 풀어 둔 채로 터미널에 입력합니다.
   ```
   flutter run --release
   ```
2. 기기를 고르라고 나오면 아이폰의 번호를 입력합니다. 처음에는 몇 분 걸립니다.
3. 맥이 "codesign이 키체인에 접근하려고 합니다"라고 물으면 맥 암호를 넣고 **항상 허용**을 누릅니다.
4. 아이폰에서 "신뢰하지 않는 개발자"라고 나오면:
   **설정 → 일반 → VPN 및 기기 관리 → 개발자 앱**에서 본인 계정을 누르고 **신뢰**합니다.
   그런 다음 홈 화면의 **휠체어 길안내** 앱을 엽니다.
5. 위치 사용을 물으면 **앱을 사용하는 동안 허용**을 누릅니다.
6. 터미널에서 `q`를 눌러 끝냅니다. 앱은 아이폰에 남습니다.

> 꼭 `--release`를 붙이세요. 빼고 설치하면 케이블을 뽑은 뒤 앱이 열리지 않습니다.

## 3. 7일마다 다시 설치하기 (무료 애플 계정)

무료 계정으로 설치한 앱은 **7일이 지나면 열리지 않습니다.** 기록은 지워지지 않으니, 아래 순서로 다시 설치하면 됩니다.

1. (앱이 아직 열릴 때) **조사 탭 → 내보내기**로 기록 사본을 카카오톡 "나에게 보내기" 등에 남깁니다.
2. 아이폰을 맥에 연결하고 2-4와 똑같이 `flutter run --release`를 실행합니다.
3. 앱을 열어 기록이 그대로 있는지 확인합니다.

> **앱을 삭제하지 마세요.** 삭제하면 기록도 함께 지워집니다. 같은 앱을 덮어 설치하면 기록이 남습니다.

꼭 지킬 것:

- 다시 설치할 때는 **처음 설치한 것과 같은 맥, 같은 애플 계정(Team)** 을 쓰세요. 다른 계정으로는 덮어 설치가 되지 않습니다.
- **설치하다 오류가 나도 앱을 지우지 마세요.** "앱을 삭제하고 다시 설치하라"는 안내가 보여도 먼저 원인을 확인하세요. 지우면 기록이 사라집니다.
- 만약 기록을 잃었다면, 마지막으로 내보낸 파일을 아래 5절 방법으로 앱에 넣어 되살릴 수 있습니다(되살린 기록은 휴대폰에서 지울 수는 없습니다). 그래서 **내보내기를 자주** 해 두는 것이 가장 중요합니다.
- 설치한 첫날, 내보내기가 실제로 되는지(카카오톡이나 에어드롭으로 파일이 가는지) 한 번 확인하세요.

## 4. 조사하는 법

1. 아래 **조사** 탭을 누릅니다.
2. 위에서 종류를 고릅니다.
3. 지도에서 **시작점**을 누르고, 이어서 **끝점**을 누릅니다. 선 하나가 기록됩니다.
   - 누른 곳이 이미 있는 길에서 15m 안이면 그 길에 자동으로 붙습니다. 선 끝이 길에 닿았는지 확인하세요.
   - 누른 곳이 다른 기록의 끝점에서 5m 안이면 정확히 그 끝점에 붙습니다. 길을 이어 그리거나, 계단 끝에서 경사로를 시작할 때 편합니다.
   - 굽은 길은 곧은 조각 여러 개로 나눠 기록합니다.
   - 잘못 눌렀으면 **취소**, 이미 기록했으면 선 가운데의 **동그란 아이콘을 눌러 삭제**합니다.

| 종류 | 언제 쓰나 | 누르는 곳 |
|---|---|---|
| **새 길** | 직접 지나가 보고 휠체어로 갈 수 있다고 확인한 걷는 길 | 길의 시작과 끝 |
| **경사로** | 휠체어용 경사로 | 경사로의 아래 끝과 위 끝 |
| **엘리베이터** | 건물 엘리베이터로 아래 길과 위 길을 이을 수 있을 때 | 아래쪽 출입구, 위쪽 출입구 |
| **계단** | 길 중간에 계단이 있을 때 | 계단의 시작과 끝 |
| **급경사** | 직접 보니 가파른 구간 | 가파른 구간의 시작과 끝 |

알아 둘 것:

- 지도의 **찻길**은 처음부터 "갈 수 있는 길"로 들어 있습니다. **걷는 길은 직접 확인해 "새 길"로 기록한 것만** 길 찾기에 쓰입니다.
- **계단·급경사는 "이미 있는 길 위"에 표시하는 종류**입니다. 찻길이나 내가 기록한 새 길 위(15m 안)에서 눌러야 길 찾기에 반영됩니다.
- **반영됐는지는 지도에서 바로 보입니다.**
  - **굵은 빨간 점선** = 길 찾기가 실제로 막은 구간, **굵은 주황 점선** = 가파르다고 표시된 구간입니다. 내가 누른 곳과 굵은 선이 다르면(엉뚱한 길이 막혔으면) 그 기록을 지우고 다시 누르세요.
  - 아이콘에 **물음표(?)** 가 붙은 계단·급경사는 **길에 반영되지 않은 기록**입니다(지도에만 표시). 아래쪽에 "길에 반영 안 됨 N건"으로 개수도 나옵니다.
  - 길이 없는 곳이라 반영되지 않았다면 그 자리에 "새 길"을 기록하세요. 계단 근처(15m 안)를 지나는 길이 생기면 "이제 길에 반영됩니다"라고 알려 줍니다.
  - 굽은 계단은 한 번에 표시하면 반영되지 않을 수 있습니다. 곧은 조각으로 나눠 기록하세요.
  - 길을 지우거나 새로 기록하면 계단·급경사의 반영 여부가 바뀔 수 있고, 바뀌면 화면 아래에 알려 줍니다.
- **계단 옆으로 돌아가는 완만한 길은 "경사로"로 기록**하세요. "새 길"로 기록하면 바로 옆 계단 표시가 그 길까지 막을 수 있습니다.
  경사로의 양 끝은 **계단 표시의 양 끝 가까이**를 누르면 됩니다(5m 안이면 계단 끝점에 정확히 붙습니다). 기록한 뒤 지도 탭에서 경사로로 길이 나는지 확인하세요.
- 찻길에서 건물 출입구로 올라가는 **짧은 경사로**도 기록할 수 있습니다. 찻길 쪽을 먼저 누르고 출입구 쪽을 누르세요.
- 기록은 바로 길 찾기에 반영됩니다. **지도** 탭에서 목적지를 골라 결과가 맞는지 현장에서 확인하세요.
- 하루 조사가 끝나면 **내보내기**로 사본을 남기세요.

## 5. 조사 결과를 앱에 넣기 (시연용 앱 만들기)

조사자가 **내보내기**로 보낸 파일(`jnu-survey-날짜-시각.json`)을 앱에 넣으면, 그 휴대폰이 아닌 다른 기기에서도 조사 결과가 반영된 길 안내가 나옵니다.

1. 내보낸 파일을 맥으로 받습니다(카카오톡, 에어드롭, 메일 등).
2. 그 파일을 이 폴더의 `assets/survey.json` 자리에 **이름을 바꿔 덮어씁니다.**
   예: 파일이 다운로드 폴더에 있다면
   ```
   cp ~/Downloads/jnu-survey-20261125-1730.json assets/survey.json
   ```
3. 파일이 멀쩡한지 확인합니다. "All tests passed!"가 나오면 됩니다.
   ```
   flutter test
   ```
4. 앱을 다시 설치합니다(아이폰은 2-4, 안드로이드·웹은 아래 6).

알아 둘 것:

- 앱에 넣은 기록은 조사 탭에서 **지울 수 없습니다.** 잘못된 기록은 내보내기 전에 조사자 휴대폰에서 지우세요.
- 조사자 휴대폰에는 같은 기록이 이미 있어도 한 번만 보입니다(겹쳐 보이지 않습니다).
- 조사가 **끝난 뒤에** 넣는 것을 권합니다. 조사 중에는 `assets/survey.json`을 `[]` 그대로 두세요.
- `dart run tool/fetch_campus.dart`(길·높이 자료 다시 받기)는 **조사를 시작한 뒤에는 실행하지 마세요.** 길 위치가 조금이라도 달라지면 기록이 붙어 있던 자리가 어긋납니다.


끝나면 `build/app/outputs/flutter-apk/app-release.apk` 파일이 생깁니다. 이 파일을 카카오톡 등으로 안드로이드 휴대폰에 보내 열면 설치됩니다.

```
flutter run -d chrome --web-port 5300 --release
```

## 7. 시연 전 점검표

- [ ] 인터넷이 됩니다 (지도 그림은 인터넷으로 받아 옵니다).
- [ ] `assets/survey.json`에 최종 조사 결과를 넣고 `flutter test`가 통과했습니다.
- [ ] 시연할 기기에 **오늘 기준 7일 안에** 설치했습니다 (아이폰 무료 계정).
- [ ] 앱을 열어 **검색 칸 → 중앙도서관**을 고르면 경로가 나옵니다.
- [ ] 강의실에서는 내 위치가 부정확할 수 있으니, **출발 → 정문**을 직접 고르는 순서를 연습했습니다.
- [ ] **수동 휠체어 / 전동 휠체어**를 바꾸면 시간과 경고가 달라지는 것을 보여 줄 수 있습니다.
- [ ] **조사 탭**에서 경로 위에 계단을 하나 기록하면 길이 돌아가는 것을 보여 줄 수 있습니다 (끝나면 그 기록은 삭제).

## 8. 알려진 한계

- **기울기는 추정값입니다.** 30m 간격의 공개 높이 자료로 계산해서 짧은 급경사는 놓칠 수 있습니다. 조사자가 본 급경사는 "급경사"로 직접 표시해야 정확합니다.
- 목적지는 건물 가운데에서 **가장 가까운 길 위의 점**까지 안내합니다. 휠체어용 출입구가 어디인지는 구분하지 않습니다.
- 지도 그림은 인터넷이 있어야 보입니다. 길 찾기 계산 자체는 인터넷 없이도 됩니다.
- 지도 그림은 오픈스트리트맵의 공개 서버에서 받습니다. 수업 시연 정도의 가벼운 사용에 맞는 서버라서, 많은 사람이 쓰는 서비스로 키우려면 별도 지도 서버가 필요합니다.
- 건물 안 안내, 음성 안내, 길을 벗어났을 때 자동으로 다시 찾기는 없습니다.
- 가파름 기준(수동 8%, 전동 12%)과 속도 같은 값은 `lib/model.dart` 맨 위에 모여 있어 쉽게 바꿀 수 있습니다.

## 만든 것이 맞는지 확인하기

```
flutter test
```

설계서의 확인 항목 8개(계단을 피하는지, 완만한 길을 고르는지, 급경사를 경고하는지 등)를 포함한 자동 검사가 모두 통과하면 "All tests passed!"가 나옵니다.
